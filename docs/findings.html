Source findings

Repository execution model

PowerDocuCLI and PowerDocuForm dispatch .msapp to AppDocumentationGenerator and .zip to SolutionDocumentationGenerator. The solution path orchestrates Canvas apps, cloud flows, agents, model-driven apps, business process flows, desktop flows, classic workflows, dataflows, AI models, and solution documentation through separate documenter projects.

Upstream output selection is All, Word, Html, or Markdown. ConfigHelper also defines Canvas changed/default behavior, sample data, Flow sort order, Word template and table-of-contents behavior, component inclusion flags, default columns, graph completeness, and update checking.

Intentional retained-core files

eng/core-diff-allowlist.txt is enforced by scripts/check-core-diff.sh. Changes are confined to Canvas generation seams, output-path composition, asset/graph interfaces and desktop implementations, and trim metadata. The pinned Common submodule remains clean; eng/patches/powerdocu-common-browser-paths.patch is applied and reversed during the browser build.

Archive boundary

BrowserArchiveGuard limits input to 100 MB, expanded content to 512 MB, individual entries to 128 MB, entries to 10,000, and compression ratio to 200:1. It rejects unreadable ZIPs, absolute paths, drive paths, relative traversal, empty path segments, and case/slash-equivalent duplicates. Processing occurs under a GUID workspace, not a shared extraction path.

Known evidence limits

  • The original desktop workflow did not finish in the Linux baseline container; native Graphviz ran, then Windows resource-path assumptions stopped documentation generation.
  • Section flags such as documentAppVariables exist in ConfigHelper but are not consumed by the Canvas HTML builder, so they are not shown in the browser UI.
  • Trimming reports reflection warnings in the retained Newtonsoft/JObject parser. Synthetic and private acceptance pass; broader package variance remains a test requirement.
